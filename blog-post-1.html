Introduction à Cypress pour les tests E2E

15 novembre 2024 · 8 min de lecture

Cypress est devenu l'un des outils de test end-to-end les plus populaires dans l'écosystème JavaScript. Dans cet article, je vous guide pas à pas pour mettre en place vos premiers tests E2E.

Pourquoi Cypress ?

Contrairement à Selenium, Cypress s'exécute directement dans le navigateur, ce qui lui confère plusieurs avantages décisifs :

  • Vitesse : les tests s'exécutent sans délais artificiels, Cypress attend automatiquement que les éléments soient disponibles
  • Debugging : le Time Travel permet de voir exactement ce qui s'est passé à chaque étape du test
  • Fiabilité : moins de tests flaky grâce à la gestion automatique des assertions asynchrones
  • Developer Experience : rechargement à chaud, console interactive, screenshots et vidéos automatiques

Installation

Cypress s'installe facilement via npm dans votre projet existant :

# Installation
npm install cypress --save-dev

# Ouverture de l'interface Cypress
npx cypress open

# Ou exécution en mode headless (CI)
npx cypress run

Lors de la première ouverture, Cypress crée automatiquement la structure de dossiers :

cypress/
├── e2e/          ← vos fichiers de test (specs)
├── fixtures/     ← données de test (JSON)
├── support/
│   ├── commands.js    ← commandes custom
│   └── e2e.js         ← configuration globale
cypress.config.js      ← configuration principale

Votre premier test

Créez le fichier cypress/e2e/login.cy.js :

describe('Page de connexion', () => {
  beforeEach(() => {
    cy.visit('/login')
  })

  it('doit permettre de se connecter avec des identifiants valides', () => {
    // Saisie des champs
    cy.get('[data-cy="email"]').type('user@example.com')
    cy.get('[data-cy="password"]').type('motdepasse123')

    // Soumission du formulaire
    cy.get('[data-cy="submit-btn"]').click()

    // Vérification de la redirection
    cy.url().should('include', '/dashboard')
    cy.contains('Bienvenue').should('be.visible')
  })

  it('doit afficher une erreur avec de mauvais identifiants', () => {
    cy.get('[data-cy="email"]').type('faux@example.com')
    cy.get('[data-cy="password"]').type('mauvais')
    cy.get('[data-cy="submit-btn"]').click()

    cy.get('[data-cy="error-message"]')
      .should('be.visible')
      .and('contain', 'Identifiants incorrects')
  })
})
💡 Conseil : utilisez les attributs data-cy sur vos éléments HTML plutôt que des classes CSS ou des IDs. Ils résistent aux refactorisations et rendent vos sélecteurs explicitement destinés aux tests.

Commandes custom

Pour éviter la répétition (DRY), créez des commandes réutilisables dans cypress/support/commands.js :

// Commande de connexion réutilisable
Cypress.Commands.add('login', (email, password) => {
  cy.request({
    method: 'POST',
    url: '/api/auth/login',
    body: { email, password }
  }).then(({ body }) => {
    window.localStorage.setItem('token', body.token)
  })
})

// Utilisation dans un test
describe('Dashboard', () => {
  beforeEach(() => {
    cy.login('admin@example.com', 'password')
    cy.visit('/dashboard')
  })
  // ...
})

Intégration dans GitHub Actions

Ajoutez ce workflow dans .github/workflows/e2e.yml :

name: Tests E2E
on: [push, pull_request]

jobs:
  cypress:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: cypress-io/github-action@v6
        with:
          build: npm run build
          start: npm start
          wait-on: 'http://localhost:3000'
          record: true
        env:
          CYPRESS_RECORD_KEY: ${{ secrets.CYPRESS_RECORD_KEY }}

Conclusion

Cypress simplifie considérablement la mise en place et la maintenance de tests E2E. Sa courbe d'apprentissage rapide et son écosystème riche en font un choix idéal pour les équipes QA modernes.
